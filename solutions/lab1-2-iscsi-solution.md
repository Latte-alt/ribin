# Лабораторная 1–2 — iSCSI на Альт Сервере 11.1

[Методичка](../Лаб%20раб%201-2%20iSCSI.docx).

**Адаптация под Альт:** сохраняются Linux SCSI Target (tgt), файл через `dd`, IQN, доступ по IP, CHAP и проверка `tgtadm`. Вместо Debian-пакета `tgt` в Альте устанавливается **scsitarget-utils**, служба — **tgt**. Подготовка VirtualBox и проверка с клиента добавлены к методичке; её основная часть заканчивается проверкой серверной цели.

## 1. Подготовка VirtualBox

Использовать имеющийся ISO **Альт Сервер 11.1 x86_64** для обеих машин. Нужен интернет основного компьютера для установки дополнительных пакетов.

Создать две ВМ через **VirtualBox → Создать**:

| Параметр | Сервер | Клиент |
| --- | --- | --- |
| Название | ALT-iSCSI-Server | ALT-iSCSI-Client |
| Тип ОС | Linux | Linux |
| Версия, если ALT отсутствует | Other Linux (64-bit) | Other Linux (64-bit) |
| ISO | Альт Сервер 11.1 | Тот же ISO |
| ОЗУ | 2048 МБ | 2048 МБ |
| Процессоры | 2 при наличии ресурсов | 1–2 |
| Новый диск VDI | **240 ГБ, динамический** | **25 ГБ, динамический** |
| Лабораторный IP | **192.168.111.149/24** | **192.168.111.150/24** |

Включить **«Пропустить автоматическую установку / Skip Unattended Installation»**, если этот пункт доступен. Для описанного стенда оставить обычную BIOS-загрузку: EFI выключен. Не выбирать полное предварительное выделение места VDI.

**240 ГБ у сервера — запас для ОС и заполнения сетевого диска на 200 ГиБ.** Динамический VDI не занимает весь максимальный объём сразу. Пустой разреженный файл можно создать и на меньшем диске, но запись данных требует настоящего свободного пространства внутри ВМ и на основном компьютере.

**В методичке два варианта на выбор:** 2 ГиБ фиксированный или 200 ГиБ разреженный. Если используешь только первый, серверу тоже можно дать системный VDI 25 ГБ. Две одинаковые виртуалки методичка не требует: вторая нужна для дополнительной проверки инициатора.

## 2. Сеть VirtualBox — на обеих машинах

При выключенной ВМ открыть **Настройки → Сеть**:

| Настройка | Адаптер 1 | Адаптер 2 |
| --- | --- | --- |
| Включить адаптер | Да | Да |
| Тип подключения | **NAT** | **Внутренняя сеть / Internal Network** |
| Имя внутренней сети | — | **iscsi-lab** |
| Кабель подключён | Да | Да |

Имя `iscsi-lab` должно совпадать у обеих машин. NAT используется для загрузки пакетов, второй адаптер — для связи сервера и клиента.

В разделе **Дополнительно** записать MAC каждого адаптера. После установки можно сопоставить их с `ip -br link`. Обычно первый интерфейс называется `enp0s3`, второй — `enp0s8`, но имена необходимо проверить.

## 3. Установка Альт Сервера 11.1

Установить систему отдельно на обе ВМ. Если Альт уже установлен, перейти к проверке сети.

1. Загрузить ВМ с ISO и выбрать **установку Альт Сервера**.
2. Выбрать язык, принять соглашение, настроить часовой пояс.
3. Выбрать редакцию **Альт Сервер**, без развёртывания домена.
4. Разметить **виртуальный диск выбранной машины**. Для простого стенда использовать корневой раздел `/` в **ext4** на основной части диска; swap — небольшой либо по предложению установщика. Загрузчик установить на этот виртуальный диск.
5. На сервере не отдавать основную ёмкость отдельному `/home`: файл `/storage/lun0.img` находится на корневом разделе.
6. Для меньшего объёма установки **не выбирать GNOME** и дополнительные серверные роли. Поддержка виртуальных окружений необязательна. Работа дальше идёт из консоли.
7. Настроить сеть по разделу 4.
8. Задать пароль **root**, создать обычного пользователя, например `student`, запомнить оба пароля.
9. Завершить установку, перезагрузить ВМ, извлечь ISO из виртуального привода, если снова открывается установщик.

## 4. Сеть в установщике Альта

Для каждого интерфейса открыть **«Дополнительно»**, выбрать **Etcnet** и включение при загрузке. Первый интерфейс NAT оставить в режиме **«Использовать DHCP»**.

Для второго интерфейса выбрать **«Вручную»**, ввести IP, выбрать маску `/24` и нажать **«Добавить»**, чтобы адрес попал в список.

| Поле | Сервер | Клиент |
| --- | --- | --- |
| Имя компьютера | iscsi-server | iscsi-client |
| IP второго адаптера | 192.168.111.149 | 192.168.111.150 |
| Маска | 255.255.255.0, или /24 | 255.255.255.0, или /24 |
| Шлюз второго адаптера | Не задавать | Не задавать |
| DNS второго адаптера | Не задавать | Не задавать |

Шлюз по умолчанию и DNS должны получаться **от NAT**. Не удалять их из общих настроек при настройке второго интерфейса. Адрес клиента `.150` взят из методички, адрес сервера `.149` выбран для стенда.

## 5. Вход и проверка сети

Войти под обычным пользователем, затем:

```bash
su -
```

Ввести **пароль root**. Символы пароля не отображаются. Все дальнейшие команды выполнять от root, без `sudo`.

На обеих машинах:

```bash
cat /etc/altlinux-release
ip -br link
ip -br address
ip route
```

Ожидается NAT-адрес, обычно `10.0.2.15/24`, и внутренний `.149/24` на сервере либо `.150/24` на клиенте. Одинаковый `10.0.2.15` на отдельных NAT-адаптерах обеих ВМ допустим. Для iSCSI используются адреса `192.168.111.x`.

### Если внутренний адрес не настроен

Если адреса уже правильные, этот блок пропустить. Он рассчитан на выбранный **Etcnet**. Для интерфейса под NetworkManager сначала выбрать Etcnet в **ЦУС → Ethernet-интерфейсы → Дополнительно** либо задать адрес через действующий менеджер.

На обеих машинах заменить `enp0s8` фактическим именем **внутреннего**, а не NAT-интерфейса:

```bash
LAB_IF=enp0s8
mkdir -p "/etc/net/ifaces/$LAB_IF"
cat > "/etc/net/ifaces/$LAB_IF/options" <<'EOF'
TYPE=eth
BOOTPROTO=static
ONBOOT=yes
DISABLED=no
CONFIG_IPV4=yes
CONFIG_IPV6=no
NM_CONTROLLED=no
SYSTEMD_CONTROLLED=no
EOF
```

**На сервере:**

```bash
printf '192.168.111.149/24\n' > "/etc/net/ifaces/$LAB_IF/ipv4address"
```

**На клиенте:**

```bash
printf '192.168.111.150/24\n' > "/etc/net/ifaces/$LAB_IF/ipv4address"
```

На обеих машинах очистить случайный шлюз/DNS **только внутреннего интерфейса**, применить из консоли VirtualBox:

```bash
: > "/etc/net/ifaces/$LAB_IF/ipv4route"
: > "/etc/net/ifaces/$LAB_IF/resolv.conf"
systemctl restart network
ip -br address
ip route
```

Первый интерфейс должен сохранить DHCP и маршрут `default` через NAT. Если этого нет — вернуть DHCP для первого интерфейса в ЦУС. Не назначать второму интерфейсу шлюз `.149` или `.150`.

### Проверка связи

**Сервер:**

```bash
ping -c 4 192.168.111.150
```

**Клиент:**

```bash
ping -c 4 192.168.111.149
```

На обеих машинах проверить DNS:

```bash
getent hosts ftp.altlinux.org
```

Если нет связи между ВМ — проверить `iscsi-lab`, кабель, разные IP и маску. Если нет интернета — проверить NAT, маршрут по умолчанию, DNS и интернет основного компьютера.

## 6. Репозитории и пакеты

На обеих машинах:

```bash
apt-repo
```

Нужны сетевые источники **p11**. Если они отсутствуют:

```bash
apt-repo add p11
```

Если APT требует установочный диск, в настройке источников отключить запись `rpm cdrom:`, оставив сетевой p11. Не подключать p10 или Sisyphus ради одного пакета.

**На сервере:**

```bash
apt-get update
apt-cache policy scsitarget-utils
apt-get install scsitarget-utils
rpm -q scsitarget-utils
```

**На клиенте:**

```bash
apt-get update
apt-get install open-iscsi
rpm -q open-iscsi
```

Подтвердить установку зависимостей. В Альте серверный пакет называется **scsitarget-utils**, не `tgt`.

После настройки удобно выключить машины через `poweroff`, сделать в VirtualBox снимки **«Альт: сеть и пакеты готовы»**, затем снова запустить обе ВМ.

## 7. Создание диска на сервере — выбрать один вариант

```bash
mkdir -p /storage
df -h /storage
ls -lh /storage/lun0.img
```

Если файл отсутствует — создавать новый. **Если существует, не выполнять `dd` поверх него.**

### Вариант A: разреженный файл 200 ГиБ

```bash
dd if=/dev/zero of=/storage/lun0.img bs=1 count=0 seek=200G
ls -lh /storage/lun0.img
du -h /storage/lun0.img
```

`ls` показывает логический размер **200G**, `du` — фактически занятое место. Вначале файл почти пустой; для заполнения требуется свободное место на разделе `/storage` и на диске основного компьютера.

### Вариант B: фиксированный файл 2 ГиБ

Выполнить **вместо варианта A**, только при отсутствии файла:

```bash
dd if=/dev/zero of=/storage/lun0.img bs=1M count=2048
ls -lh /storage/lun0.img
du -h /storage/lun0.img
```

Оба варианта взяты из методички. Указанное там преобразование `cp --sparse=always filename newfilename` — отдельный приём, для нового разреженного файла не требуется.

## 8. Настройка цели tgt на сервере

```bash
mkdir -p /etc/tgt/conf.d
cat /etc/tgt/targets.conf
```

Проверить активную строку `include /etc/tgt/conf.d/*.conf`. **Только если её нет**, добавить один раз:

```bash
printf '\ninclude /etc/tgt/conf.d/*.conf\n' >> /etc/tgt/targets.conf
```

Создать цель из методички:

```bash
cat > /etc/tgt/conf.d/debain-test.conf <<'EOF'
<target iqn.2009-02.lab.interface31:deban-test-target>
    backing-store /storage/lun0.img
    initiator-address 192.168.111.150
    incominguser andrey secretpass12
</target>
EOF

chmod 600 /etc/tgt/conf.d/debain-test.conf
systemctl enable tgt
systemctl restart tgt
```

`andrey / secretpass12` — учебные CHAP-данные из методички, а не пользователь Linux. Файл везде **lun0.img с цифрой 0**: исправлена опечатка `lunO.img`. Адрес в `initiator-address` должен совпадать с адресом клиента.

## 9. Проверка сервера — по методичке

```bash
systemctl status tgt --no-pager
tgtadm --mode target --op show
ss -lntp | grep ':3260'
```

Ожидается работающая служба, TCP **3260**, цель **iqn.2009-02.lab.interface31:deban-test-target** в состоянии **ready**, диск **LUN 1** с путём `/storage/lun0.img`, IP доступа `.150` и пользователь `andrey`. Служебный **LUN 0** типа controller не является созданным диском.

Диагностика:

```bash
journalctl -u tgt -n 50 --no-pager
rpm -ql scsitarget-utils | grep -E 'targets.conf|tgt.service|conf.d'
cat /etc/tgt/targets.conf
cat /etc/tgt/conf.d/debain-test.conf
ls -lh /storage/lun0.img
```

Если служба слушает TCP 3260, но соединение с клиента блокируется, проверить сетевой экран. В действующем средстве настройки firewall разрешить **входящий TCP 3260 от 192.168.111.150**. Весь firewall отключать не требуется.

## 10. Подключение клиента — дополнение к методичке

**На клиенте**, от root:

```bash
if [ ! -s /etc/iscsi/initiatorname.iscsi ]; then
    mkdir -p /etc/iscsi
    printf 'InitiatorName=%s\n' "$(iscsi-iname)" > /etc/iscsi/initiatorname.iscsi
fi
systemctl enable --now iscsid

ISCSI_SERVER=192.168.111.149
ISCSI_TARGET=iqn.2009-02.lab.interface31:deban-test-target

ping -c 4 "$ISCSI_SERVER"
iscsiadm -m discovery -t sendtargets -p "$ISCSI_SERVER:3260"

iscsiadm -m node -T "$ISCSI_TARGET" -p "$ISCSI_SERVER:3260" --op update -n node.session.auth.authmethod -v CHAP
iscsiadm -m node -T "$ISCSI_TARGET" -p "$ISCSI_SERVER:3260" --op update -n node.session.auth.username -v andrey
iscsiadm -m node -T "$ISCSI_TARGET" -p "$ISCSI_SERVER:3260" --op update -n node.session.auth.password -v secretpass12

iscsiadm -m node -T "$ISCSI_TARGET" -p "$ISCSI_SERVER:3260" --login
iscsiadm -m session
lsblk -o NAME,SIZE,TYPE,MODEL,MOUNTPOINT
ls -l /dev/disk/by-path/*iscsi*
```

Ожидается успешный вход, активная сессия и дополнительный диск **200 ГиБ или 2 ГиБ**, в зависимости от выбранного файла. Системный диск клиента остаётся 25 ГБ. Форматирование и монтирование методичкой не требуются.

**На сервере** повторить:

```bash
tgtadm --mode target --op show
```

В `I_T nexus information` должна появиться сессия инициатора с IP **192.168.111.150**.

Если вход отвергнут — проверить IP клиента и CHAP. Если обнаружение зависает — проверить связь, TCP 3260, службу tgt и её конфигурацию.

## 11. Завершение и сохранение

После проверки на клиенте, пока диск не используется:

```bash
iscsiadm -m node -T "$ISCSI_TARGET" -p "$ISCSI_SERVER:3260" --logout
```

Затем на обеих машинах:

```bash
poweroff
```

В VirtualBox сделать снимки **«Лаба 1–2 iSCSI настроена»**. При следующем запуске сначала запустить сервер, затем на клиенте объявить переменные и повторить `--login`; автоматический вход здесь не настроен.

## Вывод

После успешной серверной проверки: «На Альт Сервере 11.1 настроена iSCSI-цель Linux SCSI Target. Создан файловый диск, ограничен доступ по IP инициатора и настроена CHAP-аутентификация. Проверены состояние цели и параметры LUN».

Если выполнена проверка клиента, добавить: «Инициатор подключился к цели и обнаружил предоставленный сетевой диск».

**Статус:** наличие `scsitarget-utils` и `open-iscsi` проверено в официальном репозитории p11 x86_64; способы настройки сверены с документацией Альта. На виртуальных машинах установка и iSCSI-соединение здесь не запускались. Подготовка VirtualBox, IP сервера и клиентская проверка добавлены; серверная логика методички сохранена. Не монтировать обычную файловую систему одного LUN одновременно на запись на нескольких независимых клиентах.
